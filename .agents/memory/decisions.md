# Decision Log

Append-only. Never silently reverse a logged decision: add a new dated entry superseding it.

| Date | Decision | Reasoning (short) |
|---|---|---|
| 2026-11-07 | HTTP capture uses `URLProtocol` injected into `URLSessionConfiguration.default` and `.ephemeral` by swizzling their getters, not swizzling task `resume()` and delegates, and not a local proxy or VPN | Public API; Cerebro owns the real session, so metrics are exact |
| 2026-11-07 | Background URLSessions use a delegate-proxy engine | Strategy pattern: both engines feed the same pipeline |
| 2026-11-07 | Startup is one explicit `Cerebro.start(configuration)` call, not Objective-C `+load` | SPM can't link a package for Debug only, so `+load` would run in App Store builds and before any configuration exists; the linker can also drop it |
| 2026-11-07 | Off in Release unless the developer opts in at start, not compile-time removal | Each project decides whether its QA builds include Cerebro; nothing runs by accident; one binary also works as an XCFramework |
| 2026-11-07 | The engine is Swift, with unsafe pointers only at C API boundaries, not a C or C++ engine | URLSession already delivers `Data` and every decoder takes `Data`; parsing speed isn't the bottleneck |
| 2026-11-07 | `URLSessionWebSocketTask` is captured by hooks on its public `send` and `receive` Objective-C methods, not a developer-swapped task or fishhook | A wrapper forces call-site changes and makes Cerebro a production dependency; fishhook is unstable |
| 2026-11-07 | `NWConnection` is captured by a `MonitoredNWConnection` wrapper | Network.framework has no Objective-C methods to hook |
| 2026-11-07 | Third-party sockets log through `ExternalNetworkBridge` | Their engines bypass URLSession |
| 2026-11-07 | Logs live in a thread-safe ring buffer behind an actor, capped by count and by body size | Large bodies, not request count, cause out-of-memory crashes |
| 2026-11-07 | Proto rules come from code or from `traffic_map.json`, and both produce the same rules | Code rules work in every channel and are type-checked; the JSON uses proto names, so one file can be shared with Android and the backend |
| 2026-11-07 | Proto parsing uses SwiftProtobuf, not an embedded C++ parser | Binary size; apps with `.pb.swift` files already link it |
| 2026-11-07 | The dashboard is programmatic UIKit in a `PassthroughWindow` at `windowLevel = .statusBar + 1`, not presented in the host's hierarchy | Never swallows the host app's touches or disturbs its navigation state |
| 2026-11-07 | Distribution is SPM first, an XCFramework on each release, and a Git-sourced pod never pushed to trunk | CocoaPods trunk goes read-only on December 2, 2026, so a pod pushed now could never get an update |
| 2026-11-07 | `.agents/` follows the owner's bifrost repo: context, memory, plans, rules, and `.agents/skills` as a symlink to `.claude/skills` | Owner's instruction; Claude Code discovers `.claude/skills`, and the symlink gives other agents the spec's `.agents/skills` path |
| 2026-11-07 | `AGENTS.md` holds the instructions and `CLAUDE.md` imports it, unlike bifrost's symlink | The spec requires this; a symlink can't give `CLAUDE.md` Claude-only notes |
| 2026-11-07 | Added the `new-plan` and `context-sync` skills on top of the spec's four | Owner's instruction to follow bifrost for agent tooling; both are process skills with no project-specific dependency |
| 2026-11-07 | SPM tests run through a committed `.swiftpm/xcode/package.xcworkspace` | With `Cerebro.xcodeproj` in the root, plain `xcodebuild` picks the project; the workspace is what reaches the `Cerebro-Package` scheme |
| 2026-11-07 | `swift build` and `swift test` are not valid checks | They build for the Mac, and the package is iOS-only |
| 2026-11-07 | Swift 5 language mode with `StrictConcurrency` via `enableExperimentalFeature`, on 5.9 tools | The spec sets 5.9 tools; `swiftLanguageModes` needs 6.0 tools; `unsafeFlags` would stop the package being a versioned dependency |
| 2026-11-07 | Warnings are errors in `Cerebro.xcodeproj` target settings, not an `xcodebuild` override | Strict concurrency only warns in Swift 5 mode; a command-line override failed with "conflicting options" against the `-suppress-warnings` Xcode gives remote packages |
| 2026-11-07 | Removed `SWIFT_APPROACHABLE_CONCURRENCY`, `MEMBER_IMPORT_VISIBILITY` and `DEVELOPMENT_TEAM` from the Xcode template settings | The first two would compile the same sources differently from SPM; a personal team ID doesn't belong in a public project |
| 2026-11-07 | Removed the Xcode `CerebroTests` target | Tests live in `Tests/` and use `@testable` on SPM module names, which don't exist in the single-module build |
| 2026-11-07 | `-alias-module-names-in-module-interface` on `Cerebro` and `CerebroProto` | `enum Cerebro` shadows module `Cerebro`; verified that without the flag the archive fails with "'CerebroConfiguration' is not a member type of enum 'Cerebro.Cerebro'", and with it a client compiles from the interface alone |
| 2026-11-07 | `SwiftProtobuf.framework` is compiled in `Cerebro.xcodeproj` from `.build/checkouts`, with `Package.resolved` committed as the pin | Linked statically it would give the app a second copy of the module; verified `CerebroProto` links it dynamically and a client runs on a simulator |
| 2026-11-07 | SwiftProtobuf range is 1.27.0 up to, not including, 2.0.0 | 1.27.0 is the first version where `Message` is `Sendable`; 1.25.0 built but warned on `any Message.Type` |
| 2026-11-07 | `.gitkeep` is excluded through `EXCLUDED_SOURCE_FILE_NAMES` | Synchronized folders otherwise copy each one into the framework, which fails with "Multiple commands produce" |
| 2026-11-07 | Commit messages follow `@commitlint/config-conventional` with a 72-character header, not bifrost's `subject-case: lower-case` | Owner asked for concise, commitlint-valid messages; the strict rule rejects the spec's `chore: scaffold Cerebro repository` and any subject naming a type like `URLSession` |
| 2026-11-07 | No `Co-authored-by` trailer or other co-author info unless the owner asks on that commit | Owner's instruction |
| 2026-11-07 | Zero code change is the project's first priority: everything is automatic wherever iOS allows it, and a code-level API is added only when nothing automatic can reach that traffic or it improves performance | Owner's instruction. `MonitoredNWConnection` and `ExternalNetworkBridge` stay as additive exceptions, because nothing automatic can reach that traffic |
| 2026-11-07 | SPM, CocoaPods and a downloaded XCFramework are all first-class install options that behave the same | Owner's instruction. Verified by running the Example sources on a simulator through all three |
| 2026-11-07 | `CustomURLProtocol` is also registered with `URLProtocol.registerClass` | Extends the capture engine decision. A spike on an iOS 26.4 simulator showed the swizzled getters miss `URLSession.shared` and registration reaches it |
| 2026-11-07 | The Release gate is one runtime signing check in all three install options: on for simulators and development-signed apps, off otherwise unless the developer opts in | Refines "off in Release". `#if DEBUG` follows the app in SPM source, but in a prebuilt library every check reports Release, even `@_alwaysEmitIntoClient`, and an XCFramework opt-in would break the first priority. Not yet tested on a real device; PLAN-01 has the fallback |
| 2026-11-07 | Keep one `Cerebro.start()` line rather than auto-start | Owner's rule: drop it unless keeping it makes the project simpler. Spikes: a C constructor ran in SPM and dynamic Pods but was silently dropped in a static Pod, Objective-C `+load` ran there, and a pure-Swift `@_section` loader failed to link. Auto-start would add Objective-C to all three builds, a second settings route, process guards, and a check in every build. PLAN-01 has the table; PLAN-99 keeps the idea |
| 2026-11-07 | WebSocket hooks also cover `resume`, `sendPing(pongReceiveHandler:)` and `cancel(with:reason:)` | Owner's instruction. `send` and `receive` can't see open, close, or ping and pong |
| 2026-11-07 | The Proto Config tab is hidden when no proto decoder is registered | Owner's instruction. It could only ever be empty |
| 2026-11-07 | Apps that decode protobuf pass their rules to `Cerebro.start`, as the spec says, rather than having generated rules found at runtime | Same trade-off as auto-start: a lookup by name in all three install options to save one argument |
| 2026-11-07 | Each GitHub Release gives that version's exact SPM and CocoaPods lines, and the workflow fails if the tag doesn't match the podspec | Owner's request. Verified `exact: "0.1.0"` resolves a `v0.1.0` tag and a pod installs from `:tag => 'v0.1.0'` |
| 2026-11-07 | The dashboard has four tabs: HTTP, Sockets, Proto Config and System Info | Owner's choice. The spec says five but lists four; Log Inspector is a detail view opened from HTTP, and Previous session sits inside HTTP and Sockets |
